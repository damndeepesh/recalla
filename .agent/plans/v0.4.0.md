# v0.4.0 plan (all on dev; no main/release until the owner says)

## Goal

Make the capture -> memory -> injection loop observable and trustworthy, then add the per-file PreToolUse hook and the memory-quality features around it.

## Findings that shape the plan

- Assistant text IS parsed (`EventKind::AssistantText`, `harness/claude.rs`), but the live test stored none. Most likely the Stop hook reads the transcript before the final reply is flushed. Treat it as a capture race to confirm, not a design choice.
- `hook.log` only records errors, so an empty log means "no errors", not "never fired". Visibility must come from DB timestamps (`doctor`, UI), not more logging.
- `Store::supersede/archive` and the `relations` table exist. Contradiction detection does not.
- `Scope::Global` exists. Global memories are CLI/UI-only (read-only over MCP), which must stay.
- Memory uid = f(kind, scope, text), so promotion = new memory + supersede the old one.
- MCP surface is capped at 4 tools; nothing below adds a tool.

## Branches (one feature each, into dev), in order

### 1. fix/capture-and-e2e (S)

- [ ] Reproduce the missing assistant text with `claude -p` in a scratch `RECALLA_HOME`; fix the race (re-read on next capture / PreCompact / at SessionStart of the next session) or document why not.
- [ ] Fix the 2 pre-existing `make e2e` hooks failures (install/uninstall settings).
- [ ] `make live`: scripted Claude + Codex round trip (scratch data dir, `claude -p`, `codex exec` with inline MCP config). Not in CI (needs the CLIs); exits non-zero on any miss.
      Tests: e2e 82/82, regression test for the capture race.

### 2. feature/doctor (S-M)

- [ ] `recalla doctor [--json]`: binary on PATH, hooks installed (Claude), MCP registered (Claude, Codex), schema current, last capture, last injection, mirror in sync, data-dir perms. Exit 1 on any failure, with a fix hint per line.
- [ ] Reuse the `recalla ui` Connect data (`hooks_cfg`, `store/ui.rs`) so there is one source of truth.
      Tests: unit per check, integration with a broken settings file / missing DB.

### 3. feature/extract-imperative (M)

- [ ] Add labeled cases to `extract_eval` for imperative prompts ("Decision for this project: ...", "never call X in Y", "always ...", "from now on ...").
- [ ] Extend the rules; precision must stay at 52/0/0 or better.
- [ ] Measure bench extraction recall (currently 0.08) before/after.
      Tests: `extract_eval` table, redaction still first.

### 4. feature/pack-explain (S)

- [ ] `recalla pack --explain`: per memory, score parts (kind weight, recency, query match, anchor state) and why dropped under the budget. Also in the UI pack preview.
- [ ] Required before step 8 (we tune injection with it).
      Tests: golden output on a fixture pack.

### 5. feature/supersede-contradiction (M-L, Opus for the ADR)

- [ ] ADR in DESIGN_DECISIONS: what counts as a conflict (same scope + kind in {preference, decision}, shared anchor/key terms, differing value), newest wins, supersede only above a confidence margin, otherwise flag `needs_reverify` with a reason.
- [ ] Detection at extraction time in `extract::pipeline`; the write goes through `Store::supersede`.
- [ ] Reversible: `confirm` undoes it; every action visible in `why`.
- [ ] Conflict cases in `extract_eval` (tabs->spaces, WAL->rollback journal) plus negative cases that must not conflict.
      Risks: false positives hide good memories (mitigate: conservative threshold, flag over supersede when unsure).

### 6. feature/promote-global (S)

- [ ] `recalla promote <id> [--global|--project]` (CLI + UI action only, never MCP): creates the memory in the new scope, supersedes the old one, syncs the mirror.
- [ ] Pack Preferences section already reads Global; add an e2e that a promoted preference appears in a different project.
      Tests: store, mirror round trip (`rebuild --from-mirror`), scope validation.

### 7. feature/triage-ui (M, `designer` agent, Playwright check)

- [ ] Dashboard "Review" queue: needs_reverify, low confidence, flagged-by-conflict, superseded-by-conflict. Actions: confirm, forget, edit (edit = redacted new text superseding the old), promote.
- [ ] Uses the existing `ui/actions.rs` routes where possible; new routes need the security checks already in `ui::security`.
- Depends on 5 and 6. Keyboard accessible, contrast checked, one viewport screenshot at the end.
  Tests: `ui_api` tests for each action, no-JS-injection test on edited text.

### 8. feature/pretooluse-recall (L, Opus for `/plan` + review)

- [ ] First verify the PreToolUse `additionalContext` contract and matcher syntax against current Claude Code docs.
- [ ] `recalla hook pre-tool-use`: for Read/Edit/Write/MultiEdit, look up memories anchored to that path (reuse `anchor`), inject <= ~300 tokens, dedupe per session via the injection ledger so a file is injected once.
- [ ] Never blocks, exits 0, p95 < 100 ms (add to `make perf`). `hooks install` adds it with the exact-command rule; the e2e "other PreToolUse entries untouched" assertion must still hold.
- [ ] Bench: new per-file probe set; compare against session-start-only pack on tokens and right-fact recall. Ship only if it wins; otherwise keep it behind an opt-in install flag.
      Risks: noisy injection raising token cost; hook latency on large repos; stale anchors (reuse the 50 ms staleness budget).

### 9. feature/ttl-decay (S)

- [ ] Ranking decay for unconfirmed, low-confidence memories (pack score only, never deletes; confirm resets it). Measured in bench noise/staleness pillars. Surface in `--explain`.
